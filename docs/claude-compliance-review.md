# CLAUDE.md compliance follow-up

Reviewed on 2026-09-05 against `feat/phase-c-operations`. This closes the six
findings in the [original branch review](reviews/2026-09-05-claude-branch-review.md),
written against pre-fix commit `66f5de1`, and records the additional collection review.
It is not a claim that every performance suggestion has been mechanically
proved for every function: frame size, contention, monomorphization, and CPU
budgets require representative workload measurements as well as inspection.

## Original findings

1. **F1 — High:** deny-list reads acquired the same mutex twice, hanging requests and exhausting the admin permit budget.
2. **F2 — Medium:** CI omitted the required formatting and dependency-audit gates.
3. **F3 — Medium:** the config watcher performed synchronous file reads on a Tokio worker.
4. **F4 — Medium:** activity ingestion held the shared SQLite mutex during journal I/O and JSON preparation.
5. **F5 — Medium:** admin orchestration depended on concrete `FilePolicy` operations, and the credential-broker port contained its concrete adapter.
6. **F6 — Low:** cargo-deny emitted 17 duplicate-dependency warning groups despite the documented zero-warning requirement.

## Corrections

- **F1:** Removed the duplicate deny-list mutex acquisition. The new HTTP regression
  test failed on the previous implementation with a two-second timeout. It
  performs five reads (more than the four admin permits), checks the response
  contract, and then replaces the list to verify the mutation lock is free.
- **F2, F6:** Added Linux CI gates for formatting and cargo-deny 0.19.4, with
  the cargo-deny binary cached by exact version so it is not rebuilt from
  source on every run. Warnings fail the dependency gate. New duplicate
  versions are rejected; exact-version `skip` entries record the incompatible
  versions already required by the pinned graph. These are duplication
  exceptions only, not advisory or license exceptions. cargo-deny reports an
  unmatched `skip` as `error[unmatched-skip]` under `--deny warnings`
  (verified locally with a bogus entry), so a duplicate leaving `Cargo.lock`
  fails the gate until its line is deleted: removal is enforced, not
  advisory. No existing dependency pin was loosened.
- **F3:** Config reload parses the exact global-file bytes observed by the watcher.
  JSON parsing, dotenv reads, and process-config loading run on a blocking
  worker. Invalid JSON keeps the last good snapshot. The watcher no longer
  validates one read and then loads a different read of the same file.
- **F4:** SQLite projection prepares journal records before acquiring the connection
  mutex. Its worker reuses a preallocated batch, limited to 1,000 rows or about
  1 MiB of retained field/string payload (plus the record that reaches that
  threshold and vector metadata). This bounds the memory/lock-scope tradeoff.
  A panicked ingest replaces the lost batch and retries on the normal 500 ms
  cadence, as the worker did before batching, rather than retiring the
  projection. Two integration tests each span batch boundaries and compare
  every row with the journal adapter, including a subsequent query after
  journal removal: one with short records so the 1,000-row limit terminates
  a batch, and one with 2 KiB subjects so the payload limit terminates it
  first (near 240 rows).
- **F5:** Policy read/validate/diff/reload/access-review operations now use the
  application-owned `PolicyAdmin` port. File parsing, bundle locking,
  verification, and durable reload intent live in its file adapter. A second
  implementation in an HTTP integration test proves injection and error
  mapping without a local policy file. The original public `router`
  signature remains available and composes the file-backed default inside
  the HTTP adapter itself, so the adapter does not depend on the composition
  root; `router_with_policy` is the injection seam.
- **F5:** Credential broker implementations live under `auth`, and report DTOs are
  owned by the report port. Compatibility re-exports preserve downstream
  library imports. The policy adapter deliberately retains its async mutation
  lock across staging, audit append, and commit: releasing it in between would
  allow the watcher to invalidate the recorded intent. Holding a
  `tokio::sync::Mutex` across these awaits is the intended pattern, explicitly
  sanctioned by [CLAUDE.md's async synchronization guidance](../CLAUDE.md#async-synchronization--locking).
  The reason for this lock scope is documented at the lock.

## Collection and allocation guidance

| Guidance | Review and action |
| --- | --- |
| Faster hashing for trusted keys | Streaming disk transaction/reservation maps now use `FxHashMap`; their integer IDs are generated by the server, not callers. |
| HashDoS protection | Maps keyed by request subjects, token facts, key IDs, artifact IDs, and externally influenced strings retain the standard randomized hasher. Faster hashing is not a blanket replacement rule. |
| Small collections | Metric outcome counters use `SmallVec` with four inline entries and a spill path; no fixed array limit can drop a new outcome. |
| Known collection capacity | Added capacity for the config shared overlay, registered-vendor results, and Jira field-error pairs. The SQLite worker reuses its batch capacity across polls. Config lookup hits and ambiguous JWKS key IDs stay `Vec::new()`: both are usually empty, so preallocating would add an allocation to the common miss case. |
| Borrowing and hidden clones | Ambiguous JWKS IDs borrow the key set instead of cloning each ID (a lazily allocated `Vec<&str>`). Config/output-format lookups retain borrowed input; case-insensitive format selection no longer allocates a lowercase string. |
| Intermediate vectors | Report group/scope strings and SonarQube error messages join borrowed strings into one sized output buffer. Rollup cross-environment totals rescan borrowed rows instead of retaining a vector of denied-row pointers. |
| Output parity | Joining preserves empty elements, separators, order, and Unicode. Existing error/report/tool-surface tests remain the contract. |
| Necessary ownership | Values moved into `spawn_blocking` or an owned channel need ownership; the source path/config snapshots and usage-event fan-out are not gratuitous clones. Fan-out cost was already measured in the phase baseline. |
| Unknown bounds | A directory listing or open-ended stream does not have a reliable exact length. Do not preallocate an arbitrary large capacity merely to eliminate a `Vec::new()` spelling. |

`rustc-hash = 2.1.3` and `smallvec = 1.15.2` were already in `Cargo.lock`.
Their new direct dependencies use exact pins to those same versions.

These changes address inspected hot paths and clear allocation waste. They do
not certify every remaining `HashMap`, `Vec::new`, clone, boxed future, or
`format!` as optimal. Cold CLI/configuration paths and public collection types
still require contextual review; changing a public `HashMap` type solely to
save hashing time can create an API break larger than the unmeasured benefit.

- `cargo clippy --all-targets -- -D warnings`: passed.
- `cargo fmt --all -- --check`: passed.
- `cargo deny --locked check --deny warnings`: passed with refreshed advisories,

  Environment-gated live-provider tests were not independently provisioned.
- The deny-list regression failed on the unfixed code and passes after the fix.
- Allocation probe: all existing stage allocation counts and reported KB values
  match the prior C.1/Phase B baseline. JWT cache hit: 9 allocations / 1 KB /
  3.69 µs; cached actor chain: 8 / 1 KB / 3.99 µs. Journal append: 6 / 1 KB,
  p50 11 µs, p99 15 µs, max 71 µs. The 50 µs JWT and 200 µs journal p99 budgets
  hold on this machine. Config snapshots, no-filter jq, existing metric series,
  rate-limit hits, and unchanged-principal observations remain allocation-free.

## Re-review of this document (2026-09-05)

A second pass checked every claim above against commit `0c02603` and found
these gaps, all now closed:

- The projection worker exited permanently after a panicked ingest, where it
  previously retried every 500 ms. The retry is restored with a replacement
  batch (F4).
- Two "known capacity" edits preallocated for the rare case and added an
  allocation to the common miss path, contradicting the "Unknown bounds" row.
  Both reverted; the table says so.
- The projection test crossed only the payload limit. A second test with
  short records exercises the row-count terminator (F4).
- `router` fetched its default backend from `bootstrap`, giving the HTTP
  adapter a dependency on the composition root. The default is composed in
  the adapter (F5).
- The unmatched-`skip` failure was verified rather than assumed and is stated
  here and in CLAUDE.md (F2, F6).
- The CI quality job rebuilt cargo-deny from source each run; it is cached by
  exact version (F2).
- Wording (`b582381`): findings enumerated with their source, the tokio mutex
  across awaits described as the intended pattern, the test total qualified.
