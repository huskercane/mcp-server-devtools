Landing scope and deviations

ADR-013 accepted; D.1 read-only console landed. The API remains the bearer
and authorization enforcement surface. Audience selection follows the IdP
profile: Okta authorization-server setting, Entra resource-prefixed scope,
Auth0 audience, Keycloak/generic RFC 8707 resource.

The callback probes one GET /admin/policy rather than calling the validator
directly (success or 503 permits a session; 503 is not validation proof).
Health renders health_banner directly because health is not an admin
operation. Nonce is sent/stored but no ID token is consumed. htmx 4 has no
allowEval key or code-evaluation path. Session TTL uses bounded expires_in,
not decoded exp; admin calls enforce actual expiry/revocation. The embedded
script is console/static/htmx.min.js.

Runbooks cover sign-in, Strict-cookie landing, cookies, headers, Origin,
401 handling, all pages and profile-specific client registration. Plan rev
2.26 marks D.1 landed and resolves section 11 item 11 as a design decision.
CF-37 covers split-topology inventory, restart re-login and no console-session
listing; CF-38 covers every IdP section and Entra scope form remaining
unproven against a real tenant, including the known Entra SPA redemption
Origin gap; CF-39 records D.2's read-only proposals page (approve/reject stay
CLI). CF-18's would-move inventory gains src/console.
