Implementation and boundaries

Version/SHA-256-pinned cargo-deb 3.7.0 and cargo-generate-rpm 0.21.0 package
the shipping Dockerfile's x86_64 musl binary (wrds,secrets-vault, no keychain
or console). The unit has DynamicUser, StateDirectory, ProtectSystem=strict,
NoNewPrivileges and an empty CapabilityBoundingSet; the environment is
root:root 0600. Installation does not automatically enable/start a service.

Compose runs role all behind TLS with persistent journal/rollup/policy
volumes, signed policy and revocation bundles, a private checkpoint key,
file JWKS and an optional mutual-TLS syslog-ng profile. Operating docs cover
ownership, TLS, initialization, replacement, backup, upgrade and rollback.

File JWKS checks bounded regular-file contents asynchronously before cached
authentication, reparsing/installing only on content-hash change. File errors
clear keys and cached tokens, with no network fallback; withdrawal and changed
material use existing admission/invalidation logic. This replaces the proposed
timer watcher to observe withdrawal before the next cache hit. Its file-I/O
latency is outside the remote-cache probe. The fetch helper shares the Unix-only
private-output writer with auth exchange. CF-41 records portability/evidence
limits; offline licensing remains CF-10 and OVA remains on request.
