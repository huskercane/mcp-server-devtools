Implementation and operating boundaries

Textarea editing uses the existing policy/validate and policy/diff operations
through AdminClient. htmx input is debounced by 500 ms; replacement previews
swap only the result section. The API's structural rule descriptions and
validation envelope are rendered with askama escaping. Download validates the
submitted candidate again and returns its exact bytes as a no-store attachment.

A small first-party file helper JSON-escapes signed UTF-8 before ordinary form
submission, preserving CRLF/non-ASCII/signature bytes without a multipart parser,
editor widget or new dependency. The no-script path accepts the ordinary signed
API JSON envelope. Native textarea download bytes are the authoritative signing
input because form submission can normalize newlines. Upload never edits or
repairs signed bytes; the API rejects unsupported content and bad signatures.
Helper limits: 256 KiB policy / 1 KiB signature; console encoded form cap 2 MiB.

PUT /admin/policy remains the only install surface, through the configured
MutationGate. Required mode records a pending proposal without applying it;
direct mode still verifies, journals its intent and installs. Proposal review
and approve/reject forms call the existing tenant-scoped API. No gate, signature,
fresh-token, digest, expiry, idempotency, or durable-intent implementation changed.
The read API exposes proposal metadata/digest, so candidate review still needs
the offline signing handoff. CF-39 closes interactive decisions; CF-45 carries
structural-diff, review/concurrency, input-size and browser-evidence boundaries.
CF-42–44 are reserved by concurrent authorization/security documentation.

Landing-gate deviation: the clean worktree exposed five existing public TLS
fixture PEMs missing from Git because of the broad *.pem ignore. D.3 includes
the exact local test CA/server/client certificates and two leaf keys with narrow
ignore exceptions; the fixture README explicitly identifies them as throwaway
public test material. No production key or CA private key is included. Tests
now have their required inputs in a clean checkout. This does not prove hosted CI.

Local proof

Real HTTP console tests exercise validation/diff and exact downloaded-byte
sign/upload round trip, invalid signed input, audit-outage refusal without an
effect, escaping, Origin/session/security headers and encoded-body bounds.
Required-mode tests use explicit synthetic principal/token facts and the real
configured gate/on-disk signed journal: proposal without effect, self/stale/
other-tenant refusal, approval -> ordinary durable intent -> effect, repeat
approval without another record, rejection and repeated-decision refusal,
observed expiry journaled once. The offline verifier accepts the signed records.
The real RS256/wiremock JWKS login test also exercises signed policy upload.
Existing API/CLI/conformance, restart/tampered-digest and negative-matrix tests
remain active; admin_api_tests adds rejection of a signature over a document
whose only difference is newline bytes.

The optional node tests/console_upload_script_test.cjs harness executed byte
preservation (BOM/CRLF/non-ASCII/trailing newlines), malformed UTF-8, missing and
oversized files, and JSON fallback with a minimal DOM. No npm packages, Node
build requirement, real browser or real IdP tenant was introduced/exercised.
CF-38 retains provider proof; hosted CI/release evidence is not claimed.

CF-40 remains backlog only. Cargo.toml, Cargo.lock, release/benchmark profiles,
